## Resumo (com as minhas palavras)

O EC2 (Elastic Compute Cloud) fornece servidores virtuais escaláveis, as **instâncias**, para executar aplicações com flexibilidade e pagamento conforme o uso. Ao criar uma instância, escolho a **AMI** (sistema operacional), o **tipo de instância** (CPU e memória), o armazenamento, o **Security Group** (firewall) e um **Key Pair** para acesso via SSH. Serve para hospedar aplicações, criar ambientes de teste e desenvolvimento e rodar processamentos sob demanda.

## Serviços e conceitos

| Serviço / conceito | O que é | Quando usar |
|---|---|---|
| Instância EC2 | Servidor virtual na AWS | Rodar aplicações, APIs, jobs de processamento |
| AMI (Amazon Machine Image) | Imagem com o sistema operacional (Linux, Windows ou macOS) e o software de base | Escolher ao criar a instância |
| Tipo de instância | Combinação de CPU, memória e rede (ex.: `m5.2xlarge`) | Dimensionar a máquina conforme a carga |
| Security Group | Firewall virtual da instância: define quais portas e origens podem acessá-la | Liberar só o tráfego necessário |
| Key Pair | Par de chaves (pública e privada) para login via SSH | Acessar instâncias Linux pelo terminal |
| EC2 Instance Connect | Acesso SSH pelo navegador, no console da AWS | Acesso rápido a instâncias Linux, sem configurar o terminal |
| User Data | Script que roda **uma única vez**, no primeiro boot, com permissão de root | Automatizar a preparação da instância: atualizações, instalação de pacotes, download de arquivos |
| IAM Role da instância | Permissões que a instância usa para chamar outros serviços | Dar acesso a S3, DynamoDB etc. sem guardar chaves na máquina |

### Tipos de instância

**Convenção de nomes:** `m5.2xlarge`

| Parte | Significado |
|---|---|
| `m` | Classe da instância (aqui, uso geral) |
| `5` | Geração: a AWS lança gerações melhores com o tempo |
| `2xlarge` | Tamanho dentro da classe: quanto maior, mais vCPU e memória |

| Família | Otimizada para | Quando usar | Classes (exemplos) |
|---|---|---|---|
| General Purpose | Equilíbrio entre CPU, memória e rede | Cargas variadas: servidores web, repositórios de código | `t`, `m` |
| Compute Optimized | Processadores de alto desempenho | Tarefas pesadas de CPU: processamento em lote, transcodificação de mídia, servidores web de alto desempenho, HPC, modelagem científica e ML, servidores de jogos dedicados | `c` |
| Memory Optimized | Processar grandes volumes de dados em memória | Bancos de dados relacionais e não relacionais de alto desempenho, cache distribuído, bancos em memória para BI, processamento de big data em tempo real | `r` (de RAM), `x`, `z` |
| Storage Optimized | Muita leitura e escrita sequencial em disco local | Bancos OLTP de alta frequência, NoSQL, data warehouse, sistemas de arquivos distribuídos | `i`, `d`, `h` |
| Accelerated Computing | Hardware acelerador: GPUs e chips de ML | Treino e inferência de ML, IA generativa, processamento gráfico | `p`, `g`, `inf`, `trn` |
| HPC Optimized | Computação de alto desempenho em larga escala | Simulações grandes e complexas, deep learning em larga escala | `hpc` |

### Security Groups

- Controlam o tráfego que **entra** (inbound) e que **sai** (outbound) da instância.
- Só têm regras de **permissão**. Não existe regra de negação.
- Cada regra define porta, protocolo e origem (um IP/faixa de IPs ou outro security group).
- **Padrão:** toda entrada bloqueada e toda saída liberada.
- Um security group pode ser usado por várias instâncias, e uma instância pode ter vários security groups.
- Valem para uma combinação de região e VPC.
- Ficam "fora" da instância: o tráfego bloqueado nem chega até ela.

| Porta | Protocolo | Uso |
|---|---|---|
| 22 | SSH | Login em instância Linux |
| 22 | SFTP | Transferência de arquivos via SSH |
| 21 | FTP | Transferência de arquivos |
| 80 | HTTP | Sites sem criptografia |
| 443 | HTTPS | Sites com criptografia |
| 3389 | RDP | Login em instância Windows |

### Opções de compra

| Opção | Como funciona | Desconto vs. On-Demand | Quando usar |
|---|---|---|---|
| On-Demand | Paga pelo uso, sem compromisso nem custo inicial | Nenhum (preço cheio) | Cargas curtas e imprevisíveis, que não podem ser interrompidas |
| Reserved Instances | Compromisso de 1 ou 3 anos com um tipo de instância, região, sistema operacional e tenancy. A versão Convertible permite trocar o tipo (até 66%) | Até 72% | Cargas estáveis e contínuas, como um banco de dados |
| Savings Plans | Compromisso de gasto em USD/hora por 1 ou 3 anos. Fixa a família de instância e a região, mas deixa trocar tamanho, sistema operacional e tenancy | Até 72% | Uso de longo prazo, com mais flexibilidade que a Reserved |
| Spot Instances | Usa a capacidade ociosa da AWS. A instância **pode ser interrompida** a qualquer momento | Até 90% | Cargas tolerantes a falhas: processamento em lote, análise de dados, processamento de imagens |
| Dedicated Hosts | Um servidor físico inteiro só seu | Opção mais cara | Compliance ou licenças de software atreladas a socket, core ou VM (BYOL) |
| Dedicated Instances | Instâncias em hardware dedicado a você, sem controle sobre o servidor físico | — | Isolamento de hardware sem gerenciar o servidor |
| Capacity Reservations | Reserva capacidade numa AZ específica, por qualquer período | **Nenhum.** Paga o preço On-Demand mesmo sem usar | Cargas curtas que precisam de capacidade garantida numa AZ |

### Responsabilidade compartilhada no EC2

| AWS | Cliente (eu) |
|---|---|
| Infraestrutura global e segurança da rede | Regras dos Security Groups |
| Isolamento entre hosts físicos | Patches e atualizações do sistema operacional |
| Troca de hardware com defeito | Softwares instalados na instância |
| Validação de compliance | IAM Roles da instância e acesso dos usuários |
| | Segurança dos dados na instância |

## Pegadinhas de prova

- **Carga estável por 1 ou 3 anos** (ex.: banco de dados) → Reserved Instances ou Savings Plans.
- **"Pode ser interrompida" + "menor custo"** (ex.: processamento em lote) → Spot. Nunca para banco de dados ou carga crítica.
- **Licença por socket/core ou exigência de servidor físico dedicado** → Dedicated Hosts.
- **Garantir capacidade numa AZ sem compromisso longo** → Capacity Reservations, que não dá desconto.
- **Curto prazo, imprevisível e sem interrupção** → On-Demand.
- **Timeout ao acessar a instância** → problema no Security Group. **"Connection refused"** → a aplicação tem erro ou não está rodando.
- **Security Group só tem regras de permitir.**
- **User Data roda só no primeiro boot**, como root.
- **Patch do sistema operacional da EC2 é responsabilidade do cliente**, não da AWS.
- **Instância precisa acessar outro serviço** → IAM Role. Nunca rodar `aws configure` com chaves pessoais dentro da instância.
- **22 = SSH (Linux), 3389 = RDP (Windows).**

## Conexão com dados / ML

- **Accelerated Computing** é a família do ML: `p` para treino com GPU, `g` para inferência e gráficos, `inf` e `trn` para os chips da própria AWS (Inferentia para inferência, Trainium para treino). O SageMaker usa essas instâncias por baixo.
- **Spot** serve para treino barato, desde que o treino salve checkpoints e consiga continuar depois de uma interrupção. O SageMaker tem isso pronto (Managed Spot Training).
- **Memory Optimized** (`r`) serve para processar datasets grandes em memória, com pandas ou Spark.
- **User Data** pode preparar uma instância de análise sozinha: instalar Python e as bibliotecas e baixar o dataset do S3.
